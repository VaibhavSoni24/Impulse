## 1. Why E2 Exists

Candidate E2 implements **Stage 11 of PLAN.md**:
$$\text{E2} = \text{E1} + \text{structured task state}$$

The core objective is to prevent turn-to-turn context degradation and repeated exploration in multi-turn software engineering tasks. While E1 introduced an explicit pre-edit hypothesis requirement, it lacked an internal structured representation for tracking repository facts, suspect candidate locations, cumulative evidence, tactical plans, and test history across turns.

E2 provides a typed `TaskState` structure with 11 conceptual fields, deterministic JSON serialization, isolated persistence in `/tmp` (outside `/workspace` to prevent patch contamination), and bounded model context rendering.

## 4. TaskState Implementation Summary

The implementation in [`local/task_state/`](file:///E:/Projects/Impulse/local/task_state/) and re-exported in [`experiments/candidates/E2/state/`](file:///E:/Projects/Impulse/experiments/candidates/E2/state/) defines:
- **11 Conceptual Fields:** `summary`, `repository_facts`, `candidates`, `hypothesis`, `evidence`, `plan`, `edits`, `tests`, `failures`, `no_progress_count`, `final_review`.
- **Invariants:** `no_progress_count >= 0`, strict typing, non-negative progress counters, and bounded collection caps (`MAX_COLLECTION_SIZE = 50`) to prevent unbounded memory growth.
- **Model Context Rendering:** `render_model_context(state)` generates a concise markdown representation of the active state without raw multi-thousand-character command dumps.
- **Persistence Isolation:** `TaskStateManager` serializes state to `/tmp/impulse_task_state.json`, completely isolated from `/workspace` to avoid polluting `git diff HEAD`.
